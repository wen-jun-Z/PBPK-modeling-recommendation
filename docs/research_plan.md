# PBPK model recommendation research plan

Updated: 2026-09-22 (clarifying the boundary between model recommendation and blueprint construction; recommendation experiments retain the 09-14 main workflow). The objective is to assess whether recommendation algorithms select suitable PBPK models for specific uses and to validate recommendation consequences against independent observations. The existing 30 drugs, 2,872 evidence records, 202 model families, and 280 versions are retained.

When an existing model satisfies the request, model recommendation handles selection and reuse. Blueprint design addresses **the absence of a model or an existing model that does not support the intended use**: basic human PBPK + drug evidence + dosing conditions and target endpoints → a new drug module or necessary mechanism additions → an executable model; missing core evidence yields a gap-documented draft. An implementation now generates adult, single-drug, single-dose models from curated parameter evidence; support for arbitrary drugs, automatic evidence supplementation, and new mechanisms remains incomplete. Existing complete-source adaptation and calibration remain reusable tools. See the [method definition](recommendation_strategy.md#blueprint-method) for algorithms and [Section 9](#blueprint-experiments) for evaluation. Sections 1–8 remain public-model recommendation tasks; blueprint experiments do not reuse recommendation-compatibility labels, and the old large-scale search queue remains stopped.

## 1. Correct the evaluation objective first

The old catalog-compatibility labels were generated from same-drug and coverage rules, while input features contained the same information. This training round has stopped and its launch entry has been disabled; results explain the problem only, are excluded from the main paper comparisons, and will not receive additional seed runs. [Audit](../experiments/model_recommendation/runs/expanded_catalog_20260913/lambdamart_audit.json)

Adding more ranking metrics does not remove this problem. The new evaluation must distinguish relevant-model retrieval, intended-use assessment, selection among same-drug models, and actual predictive performance of recommended models. The following is the protocol proposed for this project, not conclusions already validated for us by the literature.

## 3. Labels require independent support

Define a requirement scenario as "drug + population + administration route/formulation + dose/regimen + intended use/endpoint." Candidates retain model family, version, source-code checksum, and intended use; multiple files from one model are not multiple independent models.

Keep two answer types separate:

- **Literature applicability**: blinded assessment from independently held-out reports/studies determines direct reuse, explicit adaptation, mechanistic reference only, or inapplicability. Record citations, assessors, and disagreements; use two independent annotators and adjudication when feasible. LLMs may help organize materials but are not independent judges.
- **Executed predictive capability**: compare real observations with executed outputs on studies not used to construct, fit, or select the PBPK model. Relabeling fitting data as validation after the fact is invalid. Studies with an unclear role in historical model development are initially marked "independence pending verification."

Grades 0/1/2/3 mean inapplicable/mechanistic reference/controlled adaptation/direct reuse; record null when information is insufficient. Grades must not be copied directly from identity, coverage counts, existing recommendation scores, or old validation grades. Literature applicability does not establish validated predictive accuracy.

A finding of "no applicable model" requires completed review within a predefined candidate pool. Missing downloads, missing executions, or absent observations are unknowns, not negatives. Submitted prediction files must not supply and overwrite the reference answers.

Separate inputs and answers at study/source level: different excerpts from one paper remain the same source. Hide evaluation-study curves, endpoints, conclusions, and derived validation_grade or applicability labels, rather than merely deleting the answer column. ID audits alone cannot rule out pretrained-model memorization of public data; temporal holdout and source-contamination analyses are needed.

## 4. Evaluate within-category and cross-category tasks separately

| Scenario | Question actually answered | Distinctions to preserve |
|---|---|---|
| Full-catalog content retrieval | Are evidence-supported relevant candidates found? | Score all 280 versions; unjudged items are not automatically irrelevant |
| Same drug and use, different model families | Which model better suits the study? | Main selection task; at least two independent families with distinguishable judgments/errors |
| Same drug and family, different versions | Does a version change improve applicability? | Report version comparisons separately; do not inflate independent-family counts |
| Same drug, new dose/population/route | Does the method generalize to a new scenario? | Study-level holdout; renaming a route is not adaptation |
| Same mechanism, different drugs | Can it find mechanistic references or a verifiable starting point for transfer? | Separate from direct reuse; a similar mechanism does not establish prediction for a new drug |
| Different mechanisms / no suitable candidate | Does it reject unsupported recommendations? | Distinguish inapplicable from unknown; do not optimize recommendation counts |

Every method submits all scores for identical requests and a fixed candidate pool; independently sampling a few easy negatives is prohibited. The literature-review pool first covers all same-drug candidates, plus the union of candidates from all methods and presampled hard negatives; disclose unreviewed coverage. Only fully judged request pools enter primary full-list ranking metrics. Within-pool results must not be claimed as full-catalog recall.

## 5. Multidimensional metrics and denominators

The preregistered primary ranking metric is NDCG@5 across independent same-drug families; key joint outcomes are selection regret on independent PK studies and inappropriate-recommendation rate. Undefined or unavailable metrics return null with a reason, never a substituted 0 or 1.

| Dimension | Metrics | Interpretation and limits |
|---|---|---|
| Retrieval and ranking | NDCG@1/3/5/10, Recall@k, MRR; same-drug pairwise selection accuracy | Complementary metrics of the same type; requests without positives receive separate abstention evaluation, not perfect scores; tied selections count as 0.5 |
| Intended-use assessment | Four-class use Macro-F1/confusion matrix; binary applicability F1 | Report support per class; compute literature applicability and execution success separately; do not force classes from ranking scores |
| Incorrect advice and abstention | Fraction of inapplicable candidates recommended; abstention rate when no model applies; false rejection when one applies | Rejecting everything is not best merely because errors are low; also report coverage |
| Actual prediction | GMFE and AFE/bias separately for AUC and Cmax; log error for concentration curves; fraction within preset tolerances | Same study, endpoint, and units; samples along a curve are not independent observations, and a two-fold success rule is not universally imposed |
| Recommendation consequences | Top-1 execution success, validation pass rate, selection regret | Regret = selected-model error − minimum error among fully validated candidates for the same scenario; execution failures and unknowns are separate, not omitted in favor of successful runs |
| Probability reliability | Brier, ECE, risk–coverage curves/AURC | Calibrate probabilities and abstention thresholds only on validation data; raw similarity is not probability |
| Robustness | Paraphrase consistency, change after evidence removal, sensible responses to dose/population changes | Equivalent wording should be stable; changed scientific constraints should not force blind invariance |
| Usability | Evidence support, incorrect-citation rate, qualified-family coverage; P50/P95 latency, GPU memory, throughput | Discuss diversity only among qualified candidates; do not add inapplicable drugs to inflate diversity |

Add CRPS/prediction-interval coverage only when individual observations and virtual-population distributions exist; do not fabricate a distribution from a single mean curve. [CRPS paper](https://doi.org/10.1002/psp4.70175)

Do not arbitrarily combine these dimensions into one weighted total. Main conclusions show tradeoffs among ranking, actual prediction, incorrect advice, and coverage.

## 6. Splits and fair comparison

Define separate tasks for new studies of known drugs, unseen drugs, and unseen model families; do not mix these generalization settings in one table. Split by real studies/papers and reused-data groups; duplicate versions and shared development data must not cross the corresponding cold-start boundary. Disclose when large DDI connected groups leave too few effective held-out drugs, and evaluate interpretable tasks separately rather than splitting groups and leaking data or calling two drugs comprehensive generalization.

Before training, lock each task's candidate pool, primary metrics, source isolation, applicability tolerances, and tuning budget. Methods receive identical available inputs, tuning opportunities, and hardware conditions; all parameters, thresholds, and checkpoints depend only on training/validation sets. Report zero-shot and fine-tuned results separately, as well as all-candidate reranking and two-stage retrieval; the latter also reports its recall ceiling.

The existing evaluation set has been inspected repeatedly and cannot be the sole final test of a new model. During development, use outer evaluation and inner tuning grouped by study/drug; supplement with later studies never used for selection for final validation. If unavailable, explicitly report grouped cross-validation and its limitations.

Stochastic methods use 5 prespecified seeds, with all seed results and their mean reported; deterministic methods do not fabricate five repeated samples. Cluster bootstrap by drug/study to obtain 95% intervals for paired differences, with Holm correction for multiple-model comparisons. Effective sample size is the number of independent drugs/studies, not request×candidate pairs or curve points. Insufficient drug counts preclude significance and broad-generalization claims.

## 7. Testable hypotheses for a new model (development paused)

Minimal path: structured requirements and unit normalization → text-based candidate matching → typed component-evidence graph interaction → same-drug candidate ranking → separate applicability and abstention outputs. The new model uses only information genuinely available at recommendation time.

First test three hypotheses: whether text interaction improves discrimination among same-drug models; whether component evidence adds useful information beyond a strong text baseline; and whether explicit constraints and calibration reduce incorrect intended-use recommendations. Train ranking and applicability tasks using independent labels and grouped validation rather than continuing to optimize perfect scores on old labels.

Retain only these corresponding ablations: remove component evidence, graph structure, constraints, or calibration; all variants share data and tuning budgets. Molecular information provides little candidate differentiation within one drug and is added separately only when scientifically justified for cross-drug reference/transfer. Model names and claimed innovations are not conclusions before experimental validation.

## 8. Current implementation and remaining evidence gaps

The [data-readiness inventory](../experiments/model_recommendation/scientific_evaluation/readiness.json) records actual executions and gaps. Existing Rosuvastatin validation materials, successful/failed controlled adaptations, and other Windows model outputs are reusable; the 14 Moxifloxacin curves have engineering acceptance only and are not independent scientific gold. Some old execution negatives lack observed-data protocols and must become unknowns. An LLM assertion cannot complete these role checks.

The [independent evaluation entry](../src/pbpk_kb/recommendation/model_matching/scientific_evaluation.py) implements full-candidate consistency, abstention-rule labels, source cross-checks, ranking/same-drug comparisons, applicability and probability calibration, and group support counts. Passing input audits establishes internal consistency only, not the truth of human-provided source declarations or automatic scientific acceptance.

Current applicability is binary classification; candidate-level and request-level recommendation/abstention coverage, false rejection, risk–coverage curves, and AURC have been added. Confidence ties are treated independently of ordering, and absent decisions remain unknown. Four-class intended-use predictions, independent PK selection regret, and cluster statistics remain incomplete. External baselines support full sentence reranking and removal of mechanistic support; constraint changes and new-study generalization still need independent answers. Same-drug family metrics require a prespecified representative per family; pools with duplicate versions report version-level results only. DDI multi-drug membership is supported. Per-request results retain drug and study identifiers for later paired statistics.

The evaluation entry reads one JSON file: queries stores requests/drugs/studies/tasks/candidate pools/input evidence/development studies; judgments stores independent grades, applicability, cited studies, model families, and drug membership, with unknowns explicitly null; predictions stores methods/seeds/candidate scores and optional applicability probabilities. Every method submits the full candidate pool per request. The CLI is `python -m pbpk_kb.recommendation.model_matching.scientific_evaluation --input independent_benchmark.json --output evaluation_results.json`, using the project Python wrapper. These filenames are placeholders; an independently verified benchmark has not yet been generated.

The 2026-09-14 interim snapshot contained 389 extracted and recomputed historical PK records, deduplicated to 270 observation series and exactly matched to 22 candidate artifacts available then; 13 candidates had observations. See the updated [readiness inventory](../experiments/model_recommendation/scientific_evaluation/readiness.json); snapshots covering different scopes must not be added together. Every first observation occurs after time zero, so only observation-window AUC is supported, and Cmax means the sampled-grid peak. Current requests cannot yet be linked exactly to these study scenarios, preventing independent selection-regret calculation. Remaining work includes normalization and blinded review of independent judgments, verification of all model-development sources, independent-family comparisons on common PK endpoints, and integration of some external graph/generative methods. New in-house model training is paused. Old rule labels cannot be converted to gold for this evaluator to bypass this work.

Keep the execution order simple: organize existing independent materials and same-drug candidates → freeze evaluable tasks → run every applicable baseline through one entry → develop minimal improvements for observed failure modes and ablate them → validate finally on untouched new studies. Redownloading the entire knowledge base is unnecessary, and literature-applicability work need not wait for all 280 versions to finish simulation.

Streamlit remains stopped; do not use LLMs to generate evaluation ground truth or launch old weak-label training. Model downloads and subsequent GPU inference use project-owned resources only.




## 9. Blueprint design: automated construction and updates with additional observations

Use the basic human PBPK template and traceable drug information to construct a model when no applicable existing model is available. The branch with development curves retains four-parameter vascular–tissue exchange and blood-cell partition calibration; the path without same-drug curves is evaluated separately, without mixing results. Complete implementation rules are centralized in [Recommendation strategy, Section 8](recommendation_strategy.md#blueprint-design); this file retains research questions and acceptance direction only.

**Current method: human template and drug evidence → unknown-parameter calibration → feasibility checks and necessary repair → prediction under target conditions.** When same-drug development observations exist, unknown CL is estimated by calibration against the development curve; qualified drug evidence, necessary inputs such as fu, and their sources are retained. Main text and figures consistently present the current method, without RF labels or expanded RF usage instructions. Actual RF input provenance, ablations, and parameter tests, direct predictions, and post-calibration comparisons for RF, TabPFNv2, and the CL-augmented ensemble are grouped near Appendix Table E.6. Existing experimental values remain unchanged; presentation changes do not trigger reruns. See the [recommendation strategy](recommendation_strategy.md#blueprint-rf-role) and 8.13 for parameter handling and reproduction boundaries.

The current main question is: **use simple temporal coverage to add development observations and test the practical value of automated PBPK construction and updating.** Use the existing time rule directly; beating it with a learned sampling selector is no longer a development objective or prerequisite for the paper. Test separately:

1. Whether additional information improves prediction in independent target studies compared with adding no points.
2. How the complete PBPK workflow compares with classical one- and two-compartment models under identical development observations and targets, without assuming universal superiority.
3. Whether evidence constraints, feasibility checks, and provenance offer verifiable construction and diagnostic benefits. Claims of observation savings require a separate budget experiment at matched error; one improved prediction after adding a point is insufficient.

Five-point predictions and contemporaneous baselines for the simple time rule across 30 drugs are already available for reuse.
